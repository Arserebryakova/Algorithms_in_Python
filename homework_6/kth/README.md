# K-th

## Объяснение решения

Решение сделано через функцию `find_kth_largest(nums, k)` в [solution_kth.py](solution_kth.py). Она возвращает k-й наибольший элемент с учётом повторов. Например, для `[6, 5, 5, 4]` третий наибольший — `5`. Нумерация `k` начинается с 1, исходный список не меняем.

Используем quickselect со случайным опорным и трёхчастным разбиением. После каждого разбиения продолжаем поиск только в одной части. Полную сортировку и кучи не используем.

### Как работает функция

- Проверяем, что `k` — целое число от 1 до `len(nums)`. Для пустого списка и выхода за границы вызываем `ValueError`, для неверного типа, включая `bool`, — `TypeError`.
- Копируем вход в `values`.
- Переводим номер по убыванию в индекс по возрастанию: `target = n - k`. Сортировать список для этого не нужно.
- На текущем отрезке `[left, right]` выбираем случайный опорный через `randrange(left, right + 1)`.
- Указателями `less`, `current`, `greater` делим отрезок на значения `< pivot`, `== pivot`, `> pivot`. При обмене справа не сдвигаем `current`: новый элемент ещё не проверен.
- Если `target < less`, оставляем левую часть. Если `target > greater` — правую. Иначе возвращаем `values[target]` из блока равных.

После разбиения блок равных занимает те же позиции, что после сортировки текущего отрезка. Искомый индекс либо попадает в этот блок, либо находится в одной из внешних частей. Оставляем именно её, поэтому ответ не теряется. Каждый новый отрезок строго меньше предыдущего — выбранный опорный уже исключён из дальнейшего поиска.

`target` — индекс в общем массиве, при сужении отрезка его не пересчитываем. Порядок внутри отброшенных частей для ответа не важен.

## Оценка сложности

Пусть `n` — длина списка. Сравнение и перестановку элементов считаем O(1).

**Ожидаемое время — O(n), худшее — O(n²).**

Одно разбиение отрезка длины `m` занимает O(m). Случайный опорный с постоянной вероятностью позволяет отбросить постоянную долю элементов. С учётом постоянного ожидаемого числа попыток между такими сокращениями суммарная работа ограничивается геометрической суммой и составляет O(n).

При неудачных опорных исключаем только по одному элементу: `n + (n - 1) + ... + 1 = O(n²)`. Когда все значения равны, хватает одного разбиения за O(n). Копирование входа тоже занимает O(n) времени.

**Дополнительная память — O(n).** Копия `values` занимает O(n), остальные переменные — O(1). Рекурсии нет. Если разрешить изменение входа и отказаться от копии, сам quickselect требует O(1) дополнительной памяти.

## Визуализация работы

### nums = [3, 2, 3, 1, 2, 4, 5, 5, 6], k = 4

`n = 9`, `target = 9 - 4 = 5`.

| Шаг | Активные границы | Опорный | Весь массив после разбиения | Блок равных | Решение |
| --- | --- | --- | --- | --- | --- |
| 1 | `[0, 8]` | 3, индекс 2 | `[2, 1, 2] \| [3, 3] \| [5, 5, 6, 4]` | `[3, 4]` | `5 > 4`, идём вправо: `[5, 8]` |
| 2 | `[5, 8]` | 5, индекс 5 | `[2, 1, 2, 3, 3] \| [4] \| [5, 5] \| [6]` | `[6, 7]` | `5 < 6`, идём влево: `[5, 5]` |
| 3 | `[5, 5]` | 4, индекс 5 | `[2, 1, 2, 3, 3] \| [4] \| [5, 5, 6]` | `[5, 5]` | `target` в блоке равных |

**Ответ: `4`.** Обе пятёрки учитываются отдельно: первыми четырьмя по убыванию были бы `6, 5, 5, 4`.
