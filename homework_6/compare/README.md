# Compare

## Объяснение решения

Решение сделано через функции `merge_sort(nums)`, `quick_sort(nums)` и декоратор `timer` в [solution_compare.py](solution_compare.py). Сортировки возвращают новый список по возрастанию. Исходный список не меняем. Для пустого списка возвращаем `[]`.

### Сортировка слиянием

- Копируем вход в `result`, создаём общий `buffer` для слияний.
- Вложенная функция `sort(left, right)` сортирует полуинтервал `[left, right)`.
- Если в нём меньше двух элементов, завершаем вызов.
- Иначе делим отрезок пополам и рекурсивно сортируем обе половины.
- Сливаем их в буфер: указатели `i` и `j` идут по половинам, каждый раз выбираем меньший из доступных элементов.
- Переносим готовый отрезок обратно в `result`.

Перед слиянием обе половины уже отсортированы. Выбирая меньший из первых оставшихся элементов, получаем отсортированный отрезок со всеми исходными значениями. При равенстве берём элемент слева через `<=`, поэтому mergesort устойчивый.

### Быстрая сортировка

- Копируем вход в `result`.
- В `_partition` выбираем последний элемент отрезка как `pivot`. Границы `left` и `right` включительные.
- Одним проходом делим отрезок на значения `< pivot`, `== pivot`, `> pivot`.
- `less` обозначает начало блока равных, `current` — первый непроверенный элемент, `greater` — конец непроверенной части.
- При обмене с правой границей не увеличиваем `current`: перенесённый элемент ещё нужно проверить.
- Блок равных уже на своих местах. Рекурсивно сортируем меньшую внешнюю часть, большую обрабатываем циклом в том же вызове.

Разбиение сохраняет элементы и устанавливает порядок между тремя частями. После сортировки внешних частей весь отрезок упорядочен. Обработка меньшей части через рекурсию ограничивает глубину стека O(log n), даже если опорные неудачные.

Последний элемент выбран намеренно: на упорядоченных входах получаем плохие разбиения и заметную разницу с mergesort.

### Декоратор времени

`timer` возвращает обёртку `wrapper(*args, **kwargs)`. Через `perf_counter()` получаем время до и после вызова. Разницу печатаем в секундах и сохраняем в `last_elapsed`. Результат функции возвращаем без изменений, `@wraps(func)` сохраняет её имя и документацию. Благодаря `finally` время записывается и при исключении.

Оборачиваем внешний вызов сортировки: `timer(merge_sort)(nums)`. Внутренние рекурсивные вызовы отдельно не измеряем. В замер входят копирование входа и создание буфера, вывод времени выполняется после замера.

В [benchmark.py](benchmark.py) сравниваем пять видов входов длины 3000. Случайные данные создаём через `Random(42)`. Для каждого алгоритма делаем прогрев и пять измерений, берём медиану. Порядок запусков чередуем. Генерация данных и проверка результата через `sorted` находятся вне замера.

Результат запуска 19 ноября 2026 года, Python 3.9.6, macOS, arm64:

| Вход | Mergesort, мс | Quicksort, мс | Quicksort / mergesort |
| --- | --- | --- | --- |
| Случайная перестановка | 3.719 | 3.081 | 0.83 |
| По возрастанию | 2.894 | 250.818 | 86.67 |
| По убыванию | 2.988 | 251.473 | 84.15 |
| Все равны | 2.671 | 0.103 | 0.04 |
| Пять различных значений | 3.118 | 0.384 | 0.12 |

На возрастающем входе quicksort примерно в 87 раз медленнее: крайний опорный приводит к квадратичному времени. На одинаковых элементах он примерно в 26 раз быстрее: трёхчастное разбиение сразу завершает сортировку за O(n), а mergesort выполняет O(n log n) работы. При пяти различных значениях блоки равных тоже позволяют быстро сократить задачу.

## Оценка сложности

Пусть `n` — длина списка. Сравнение и перестановку элементов считаем O(1).

| Алгоритм | Время | Дополнительная память с учётом копии входа |
| --- | --- | --- |
| Рекурсивный mergesort | O(n log n) во всех случаях | O(n) |
| Рекурсивный quicksort | В среднем O(n log n), в худшем O(n²) | O(n) |
| Quicksort, все значения равны | O(n) | O(n) |

У mergesort O(log n) уровней и O(n) работы на каждом. Результат и буфер занимают O(n), стек рекурсии — O(log n).

У quicksort разбиение линейно по длине отрезка. Сбалансированные разбиения дают O(n log n), отделение по одному элементу — сумму `n + (n - 1) + ... + 2 = O(n²)`. Средняя оценка относится к случайной перестановке различных чисел. Если все значения равны, хватает одного разбиения.

В quicksort копия занимает O(n), рекурсивный стек — O(log n), поскольку рекурсивно сортируем только меньшую часть. Без учёта возвращаемой копии дополнительная память — O(log n).

Декоратор добавляет O(1) времени и памяти на внешний вызов при фиксированном количестве аргументов и длине имени функции. Работу самой сортировки считаем отдельно. Для пустого и одноэлементного входа время и память — O(1).

## Визуализация работы

### Mergesort: nums = [7, 2, 5, 2, 9, 1, 4]

Деление соответствует середине `(left + right) // 2`:

```text
                 [7, 2, 5, 2, 9, 1, 4]
                  /                 \
             [7, 2, 5]          [2, 9, 1, 4]
              /     \             /       \
            [7]    [2, 5]       [2, 9]    [1, 4]
                    / \         / \        / \
                  [2] [5]     [2] [9]    [1] [4]
```

Слияния в порядке выполнения реализации:

| Шаг | Левая часть | Правая часть | Результат слияния |
| --- | --- | --- | --- |
| 1 | `[2]` | `[5]` | `[2, 5]` |
| 2 | `[7]` | `[2, 5]` | `[2, 5, 7]` |
| 3 | `[2]` | `[9]` | `[2, 9]` |
| 4 | `[1]` | `[4]` | `[1, 4]` |
| 5 | `[2, 9]` | `[1, 4]` | `[1, 2, 4, 9]` |
| 6 | `[2, 5, 7]` | `[1, 2, 4, 9]` | `[1, 2, 2, 4, 5, 7, 9]` |

В последнем слиянии последовательно выбираем `1` справа, `2` слева, `2` справа, `4` справа, `5` слева, `7` слева и оставшееся `9` справа.

### Quicksort: тот же массив

Первое разбиение: `pivot = 4`, `less = current = 0`, `greater = 6`. В таблице записано состояние **после** действия.

| Шаг | Действие | Массив | less | current | greater |
| --- | --- | --- | --- | --- | --- |
| 0 | Начало | `[7, 2, 5, 2, 9, 1, 4]` | 0 | 0 | 6 |
| 1 | `7 > 4`, обмен с правой границей | `[4, 2, 5, 2, 9, 1, 7]` | 0 | 0 | 5 |
| 2 | `4 == 4`, сдвигаем current | `[4, 2, 5, 2, 9, 1, 7]` | 0 | 1 | 5 |
| 3 | `2 < 4`, обмен с less | `[2, 4, 5, 2, 9, 1, 7]` | 1 | 2 | 5 |
| 4 | `5 > 4`, обмен справа | `[2, 4, 1, 2, 9, 5, 7]` | 1 | 2 | 4 |
| 5 | `1 < 4`, обмен с less | `[2, 1, 4, 2, 9, 5, 7]` | 2 | 3 | 4 |
| 6 | `2 < 4`, обмен с less | `[2, 1, 2, 4, 9, 5, 7]` | 3 | 4 | 4 |
| 7 | `9 > 4`, правая граница уменьшается | `[2, 1, 2, 4, 9, 5, 7]` | 3 | 4 | 3 |

Теперь `current > greater`: получены `[2, 1, 2] | [4] | [9, 5, 7]`.

Обе внешние части имеют длину 3. По ветке `else` сначала рекурсивно сортируем правую: опорный `7` даёт `[5] | [7] | [9]`. После возврата циклом сортируем левую: опорный `2` даёт `[1] | [2, 2] | []`.

**Итог обеих сортировок: `[1, 2, 2, 4, 5, 7, 9]`.**
