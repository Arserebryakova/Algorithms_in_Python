# Iterative

## Объяснение решения

Решение сделано через функции `merge_sort(nums)` и `quick_sort(nums)` в [solution_iterative.py](solution_iterative.py). Обе сортировки работают без рекурсии и возвращают новый список по возрастанию. Исходный список не меняем.

### Итеративный mergesort

- Копируем вход в `result`, создаём буфер той же длины.
- Считаем отдельные элементы отсортированными блоками ширины `width = 1`.
- Сливаем соседние блоки в `buffer`. Каждый раз выбираем меньший из первых оставшихся элементов.
- Границы ограничиваем длиной списка через `min`, поскольку последний блок может быть неполным.
- После прохода меняем `result` и `buffer` местами и удваиваем `width`.
- Когда `width >= n`, возвращаем `result`.

Перед каждым проходом блоки ширины `width` отсортированы. Слияние соседних блоков создаёт отсортированные блоки вдвое большей ширины. В конце весь список становится одним таким блоком. При равенстве берём элемент слева, поэтому сортировка устойчива.

### Итеративный quicksort

- Копируем вход, в `stack` кладём границы `(0, n - 1)`, если элементов больше одного.
- Достаём отрезок и делим его на значения меньше, равные и больше опорного. Опорный — последний элемент, границы включительные.
- Используем такое же трёхчастное разбиение, как в Compare. Блок равных больше не обрабатываем.
- Большую внешнюю часть кладём в стек, если в ней хотя бы два элемента. Меньшую обрабатываем внутренним циклом.
- Когда текущая часть закончилась, берём следующий отрезок из стека. Пустой стек означает конец сортировки.

После разбиения между частями уже выполнен нужный порядок. Каждая внешняя часть либо обрабатывается сразу, либо остаётся в стеке, поэтому работа не теряется. После обработки всех частей весь список отсортирован.

Сразу обрабатываем меньшую часть, чтобы число одновременно отложенных отрезков не превышало O(log n). При равных длинах откладываем левую часть и продолжаем правую.

## Оценка сложности

Пусть `n` — длина списка. Сравнение и перестановку элементов считаем O(1).

| Алгоритм | Время | Дополнительная память с учётом копии входа |
| --- | --- | --- |
| Итеративный mergesort | O(n log n) во всех случаях | O(n) |
| Итеративный quicksort | В среднем O(n log n), в худшем O(n²) | O(n) |
| Quicksort, все значения равны | O(n) | O(n) |

У mergesort O(log n) проходов, поскольку ширина блоков удваивается. На каждом обрабатываем O(n) элементов. Результат и буфер занимают O(n) памяти.

У quicksort одно разбиение линейно по длине отрезка. При сбалансированных разбиениях получаем O(n log n), при отделении по одному элементу — O(n²). Среднюю оценку рассматриваем для случайной перестановки различных чисел. Для одинаковых значений хватает одного прохода.

Копия входа занимает O(n), явный стек quicksort — O(log n). Без учёта возвращаемой копии дополнительная память quicksort — O(log n). Рекурсивного стека в этих реализациях нет. Для пустого и одноэлементного входа время и память — O(1).

## Визуализация работы

### Mergesort: nums = [7, 2, 5, 2, 9, 1, 4]

Вертикальные черты отделяют отсортированные блоки после прохода.

| Состояние | Ширина входных блоков | Слияния | Результат |
| --- | --- | --- | --- |
| Начало | — | Каждый элемент уже отсортирован | `[7] \| [2] \| [5] \| [2] \| [9] \| [1] \| [4]` |
| Проход 1 | 1 | `[7]+[2]`, `[5]+[2]`, `[9]+[1]`, `[4]+[]` | `[2, 7] \| [2, 5] \| [1, 9] \| [4]` |
| Проход 2 | 2 | `[2, 7]+[2, 5]`, `[1, 9]+[4]` | `[2, 2, 5, 7] \| [1, 4, 9]` |
| Проход 3 | 4 | `[2, 2, 5, 7]+[1, 4, 9]` | `[1, 2, 2, 4, 5, 7, 9]` |

В первом слиянии второго прохода указатели выбирают `2` слева, `2` справа, `5` справа, затем оставшееся `7` слева. Последний блок длины 1 не теряется: на первом проходе его копируем, на втором сливаем с `[1, 9]`. После третьего прохода ширина становится 8, а `8 >= 7`, поэтому цикл заканчивается.

### Quicksort: тот же массив

Стек записан слева направо от дна к вершине; `pop()` берёт последнюю пару. В отрезках используются индексы с нуля.

| Шаг | Обрабатываемый отрезок | Опорный | Состояние после разбиения | Стек после откладывания | Следующее действие |
| --- | --- | --- | --- | --- | --- |
| 0 | — | — | `[7, 2, 5, 2, 9, 1, 4]` | `[(0, 6)]` | Достаём `(0, 6)` |
| 1 | `(0, 6)` | 4 | `[2, 1, 2] \| [4] \| [9, 5, 7]` | `[(0, 2)]` | Сразу обрабатываем `(4, 6)` |
| 2 | `(4, 6)` | 7 | `[2, 1, 2, 4] \| [5] \| [7] \| [9]` | `[(0, 2)]` | Части длины 1 готовы; достаём `(0, 2)` |
| 3 | `(0, 2)` | 2 | `[1] \| [2, 2] \| [4, 5, 7, 9]` | `[]` | Меньшая часть пуста, отложенной работы нет |

На шаге 1 длины внешних частей одинаковы, поэтому код откладывает левую часть и продолжает правую. На шаге 3 обе двойки сразу попадают в блок равных, повторного разбиения для них нет.

**Результат обеих сортировок: `[1, 2, 2, 4, 5, 7, 9]`.**
